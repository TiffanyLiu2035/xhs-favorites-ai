# 小红书主站收藏夹 Agent 改版方案 —— 从信息坟场到「薯管家」个人知识库

> 本文档持续更新，记录从需求洞察到产品设计的完整思考过程。

**痛点发现：** 小红书用户普遍存在"电子囤积癖"——收藏了大量笔记却从不整理，收藏夹沦为"信息坟场"。用户想用时找不到、内容过期不知道、信息零散无法转化为行动。

**设计方案：** 引入「薯管家」AI Agent，通过智能分类、知识提炼、对话式交互三层递进架构，将收藏夹从"囤了不用"的信息坟场，升级为"收藏即可用"的个人知识库。用户无需手动整理，一句话即可触发 Agent 完成分类、搜索、总结、行程规划等操作。

## 一、问题发现

### 1.1 核心痛点：电子囤积癖

小红书用户普遍存在"电子囤积癖"——收藏了大量笔记但从不整理，导致收藏夹变成"信息坟场"。

**用户行为特征：**
- 看到有用的内容就随手收藏，但几乎不会回头整理
- 收藏量越大，找回特定内容的难度越高
- 很多收藏的内容其实已经过时或失效
- 想"用"收藏时无从下手（比如收了 50 篇穿搭但不知道怎么整合）

**需求验证：**
- 小红书社区内存在大量收藏整理相关的求助帖
- 身边用户调研中，受访者普遍表示对收藏整理功能有强烈需求
- 社区真实用户声音（评论区采集）：
  - "总有一天能出个功能，每天推送一篇尘封多年的收藏夹里的帖子总结给我"——**用户期待平台主动激活沉睡收藏**
  - "收藏夹太多了，能不能帮忙整理所有？"——**直接验证了 AI 整理的核心需求**
  - "希望每天某个时间，把最近收藏夹里收藏的东西总结分类分发过去"——**用户期待定期自动整理+推送**
- 竞品动态：OPPO 小布记忆已实现攻略类内容自动标注地点功能，说明市场已有先行者验证方向可行

### 1.2 现有收藏功能的不足

小红书当前的收藏功能仅提供简单的"收藏集"能力：
- 需要用户手动创建分类并逐一归档——但几乎没人做
- 缺少智能化的整理、检索和利用手段
- 收藏后的内容与用户之间缺少进一步的互动

## 二、数据梳理：用户收藏旅程分析

> 按用户使用收藏夹的完整生命周期拆解，每个阶段识别行为数据、断裂点和机会点。

### 2.1 阶段一：收藏（Collect）— 冲动囤积

**用户行为：** 浏览 feed / 搜索结果时，看到"可能有用"的内容随手收藏。

**行为数据画像：**
- 收藏动机分布：实用备查（攻略/教程）60%、灵感保存（穿搭/装修）25%、情绪收藏（好看/有趣）15%
- 收藏频率：活跃用户日均收藏 3-8 条
- 收藏时的决策成本：极低（< 1 秒），几乎不经过"我以后会不会用"的判断
- 收藏后的下一步行为：95% 的情况是继续浏览，不做任何整理

**断裂点：** 收藏门槛太低 + 无整理引导 = 从第一步就埋下了"囤而不用"的隐患。

**机会点：**
- 收藏时提供轻量级的"智能归类建议"（如：检测到这是一篇旅行攻略，自动建议归入旅行分类）
- 收藏后的 toast 提示中嵌入整理入口

### 2.2 阶段二：沉淀（Accumulate）— 无序膨胀

**用户行为：** 收藏夹持续增长，内容跨越多个品类和时间段，但始终保持时间倒序的扁平结构。

**行为数据画像：**
- 用户收藏总量分布：轻度用户 50-200 条，中度 200-1000 条，重度 1000+（如你的 4486 条）
- 品类分布：通常集中在 3-5 个主要兴趣领域，但混杂在一起
- 手动创建收藏集的用户比例：预估 < 5%
- 时间跨度：很多收藏来自数月甚至数年前

**用户分型观察：**
沉淀阶段的用户可分为两类，对后续方案设计有重要影响：
- **A 类（有序型）**：收藏多且专辑分得也多，喜欢自己维护有序状态 → 需要"增量归档"而非"重新分类"
- **B 类（无序型）**：收藏多但分类少，只点收藏不整理 → 需要"从零建立结构"
- 两类用户对"AI 自动分类"的期待不同，方案设计需差异化处理（详见四、解决方案 4.3 第一层）

**断裂点：** 平台没有提供任何"自动化整理"能力，完全依赖用户主动行为——而人的本性是不整理的。

**机会点：**
- **这就是我们核心方案的切入点**：AI 一键整理，在沉淀阶段为用户自动建立结构
- 定期提醒用户"你的收藏夹又增加了 X 条，要不要整理一下？"

### 2.3 阶段三：回找（Retrieve）— 大海捞针

**用户行为：** 在某个特定场景下（如出行前、换季、做决策时），用户回到收藏夹想找之前收藏的内容。

**行为数据画像：**
- 收藏夹回访率：预估仅 15-25% 的收藏内容会被用户回访
- 回找方式：翻列表（效率极低）、使用搜索（如果记得关键词）
- 找到率：在 200+ 条收藏中，成功找到目标内容的概率随数量增长急剧下降
- 找不到后的行为：重新搜索 → 重新收藏（产生重复收藏）

**断裂点：** 缺少有效的检索和导航手段，用户的查找成本与收藏量成正比。

**机会点：**
- AI 分类后，用户可以直接进入对应分类查找，将 O(n) 查找降为 O(1)
- 智能标签提供多维检索入口（按地域、价位、场景等）
- 搜索增强：AI 理解语义搜索（"之前收的那个上海人均 80 的日料"）

### 2.4 阶段四：使用（Act）— 信息过载

**用户行为：** 找到了相关内容，但面对同一主题的多篇笔记，不知道如何综合利用。

**行为数据画像：**
- 收藏→实际行动的转化率：预估 < 10%
- 典型场景：收了 30 篇成都攻略，但最终还是自己重新搜索或问朋友
- 原因：每篇笔记信息零散、互有重叠、质量参差，用户缺乏综合判断能力

**断裂点：** 从"信息收集"到"做出决策/付诸行动"之间缺少桥梁。

**机会点：**
- **AI 知识提炼**：自动总结同分类下多篇笔记的核心信息，生成结构化摘要
- **Todo 生成**：将收藏内容转化为可执行的行动清单
- **Agent 交互**：用户可以对话式地让 AI 基于收藏完成具体任务（"帮我排一个三天成都行程"）

### 2.5 阶段五：清理（Maintain）— 从不发生

**用户行为：** 几乎没有用户主动清理收藏夹，导致过期、失效、重复的内容持续累积。

**行为数据画像：**
- 主动清理收藏的用户比例：预估 < 3%
- 过期内容占比：收藏 1 年以上的笔记中，预估 20-30% 已失去时效性（关闭的店、结束的活动、下架的商品）
- 重复收藏率：同一用户重复收藏相似内容的比例预估 10-15%

**断裂点：** 清理是逆人性的行为，没有工具辅助几乎不会发生。

**机会点：**
- AI 自动识别过期内容，一键批量清理
- 重复内容检测与合并建议
- 定期"收藏体检"，推动用户维护收藏质量

### 2.6 用户旅程全景图

```
收藏(Collect) → 沉淀(Accumulate) → 回找(Retrieve) → 使用(Act) → 清理(Maintain)
   ↓                ↓                  ↓               ↓              ↓
冲动收藏         无序膨胀           大海捞针         信息过载         从不发生
   ↓                ↓                  ↓               ↓              ↓
【收藏时归类建议】【AI一键整理】   【分类+标签+搜索】 【知识提炼+Agent】【过期清理】
   轻量引导        ⭐ 核心方案        提升检索效率     驱动行动转化     保持健康
```

## 四、解决方案

### 4.1 产品定位

**让收藏从"囤"变为"用"。**

不只是一个收藏管理工具，而是基于收藏内容的个人知识助手。

### 4.2 方案与用户旅程的对应关系

我们的解决方案精准对应用户旅程中每个阶段的断裂点：

| 旅程阶段 | 断裂点 | 解决方案 | 功能层级 |
|----------|--------|----------|----------|
| 收藏 | 无分类意识 | 收藏时智能归类建议 | 前置引导 |
| 沉淀 | 无序膨胀 | AI 一键智能整理（自动分类+标签） | 第一层：整理 |
| 回找 | 大海捞针 | 分类导航 + 多维标签 + 语义搜索 | 第一层：整理 |
| 使用 | 信息过载 | 知识提炼 + Todo 生成 + Agent 交互 | 第二层+第三层 |
| 清理 | 从不发生 | 过期识别 + 一键清理 + 收藏体检 | 第一层：整理 |

### 4.3 功能设计：三层递进架构

#### 第一层：智能整理（解决"找不到"）

覆盖旅程阶段：沉淀 → 回找 → 清理

##### 用户分型与差异化策略

在执行整理前，AI 先对用户的收藏状态进行"诊断"，识别用户类型并走不同的整理路径：

**A 类用户：有序型（收藏多 + 专辑/分类多）**
- 用户画像：喜欢自己管理收藏，已建立个人分类体系
- 核心需求：不是"帮我建分类"，而是"帮我把新收藏放进已有分类"
- 整理策略：
  - AI 学习用户已有专辑的命名风格和内容特征
  - 将未归类收藏自动匹配到已有专辑中
  - 对无法匹配的内容，建议新增分类（而非强行归入已有类别）
  - 入口文案差异："发现 128 条未归类收藏，建议归入你现有的 5 个专辑"
- 设计原则：**尊重用户已有结构，增量补充，不破坏秩序**

**B 类用户：无序型（收藏多 + 分类少/无）**
- 用户画像：只点收藏不整理，收藏夹完全扁平无结构
- 核心需求：从零建立分类体系，且越省事越好
- 整理策略：
  - AI 从零分析全部收藏内容，自动生成完整分类方案
  - 先展示分类预览（分类名 + 数量 + 示例内容），用户确认后执行
  - 提供"一键接受全部"和"逐个调整"两种操作路径
  - 入口文案差异："发现 4486 条收藏，建议分为 8 个智能分类"
- 设计原则：**从无到有，一键建立结构，零操作成本**

**诊断逻辑：**
- 已有专辑数 >= 3 且专辑内笔记占比 > 30% → A 类
- 其他情况 → B 类
- 边界情况（有少量专辑但覆盖率低）→ 默认 B 类，但保留已有专辑

- **自动分类**：AI 识别笔记内容，自动归入分类（美食/穿搭/旅行/护肤/家居/学习等）
  - 分类粒度：一级分类 6-10 个，用户可自定义调整
  - 多标签支持：一篇笔记可属于多个分类（如"成都火锅推荐"同时归入美食和旅行）
- **自动打标签**：为每条笔记生成多维标签（地域、价位、场景、风格等）
  - 标签体系：自动生成 + 用户可手动补充
  - 支持按标签筛选和交叉检索
- **过期识别**：标记可能已过时的内容（已结束的活动、已关闭的店铺等）
  - 识别维度：时间衰减、内容类型（限时活动/季节性/时效性强的推荐）
  - 展示方式：灰色标记 + 过期原因说明
- **过时清理**：引导用户清理过期、失效、重复的收藏内容
  - 一键批量清理过期内容
  - 重复内容检测与合并建议
  - 清理后反馈："已为你清理 X 条过期内容，释放收藏夹空间"

#### 第二层：知识提炼（解决"用不起来"）

覆盖旅程阶段：使用

- **智能总结**：每个分类生成内容摘要，提炼关键信息
  - 例："你收藏了 23 篇美食笔记，主要集中在北京和成都，偏好人均 50-100 的餐厅"
  - 摘要随收藏更新自动刷新
- **Todo 生成**：根据收藏内容自动生成待办事项
  - 旅行收藏 → "出发前待办：签证、酒店、交通..."
  - 书单收藏 → "阅读计划：本周读《XX》第1-3章"
  - 购物收藏 → "待购清单：XX面霜（3家店铺比价）"
- **知识沉淀**：将零散收藏结构化为可用的知识库
  - 跨笔记信息提取与整合
  - 形成主题化的知识卡片

不同分类产出不同形态的结果：

| 分类 | 提炼形态 | 具体示例 |
|------|----------|----------|
| 书单 | 阅读 Todo + 知识摘要 | "5本书的核心观点对比 + 建议阅读顺序" |
| 旅行攻略 | 行程规划 Todo | "成都3天行程：Day1 春熙路→宽窄巷子..." |
| 美食收藏 | 美食地图 | "按地区/价位整理的餐厅清单 + 评分" |
| 穿搭 | 搭配灵感板 | "按场景分类：通勤/约会/休闲 各3套" |
| 护肤美妆 | 产品对比表 | "面霜横评：价格/成分/肤质适配" |
| 健身运动 | 训练计划 | "每周训练安排 + 动作要点摘要" |

#### 第三层：Agent 交互（解决"不知道怎么用"）

覆盖旅程阶段：使用（深度）

- **入口设计**：在分类详情页底部提供 Agent 对话入口
- **能力范围**：
  - 基于当前分类的收藏内容进行对话
  - 可以跨分类调用信息（"结合我的美食和旅行收藏，帮我规划周末"）
  - 支持多轮对话，逐步细化需求
- **示例交互场景**：

| 场景 | 用户说 | Agent 做 |
|------|--------|----------|
| 旅行规划 | "帮我从收藏的攻略里拼一个三天的成都行程" | 综合多篇攻略，生成分天行程 + 餐厅推荐 + 交通建议 |
| 阅读决策 | "这些书哪几本适合周末两天读完" | 按篇幅/难度筛选，推荐 2-3 本 + 理由 |
| 购物决策 | "我收藏的这些面霜，哪个适合干皮冬天用" | 对比成分/价格/用户评价，给出推荐 |
| 穿搭建议 | "明天面试穿什么，从我收藏里找灵感" | 筛选正式/职业风搭配，组合推荐 |

#### 横向能力：智能触达（让收藏主动来找你）

贯穿三层之上，解决"用户不会主动来"的问题。来源于社区用户的真实呼声。

- **每日收藏回顾（"今日回忆"）**
  - 每天推送 1-3 篇"尘封收藏"，附带 AI 总结
  - 类似 Readwise 的每日回顾 / Apple Photos 的"回忆"
  - 激活沉睡内容，让用户重新发现被遗忘的好内容
  - 用户反馈原话："总有一天能出个功能，每天推送一篇尘封多年的收藏夹里的帖子总结给我"

- **定期收藏摘要（"收藏周报"）**
  - 每天/每周自动将最近新增的收藏按分类总结，推送给用户
  - 例："本周你收藏了 12 条新内容，其中美食 5 条、旅行 4 条、穿搭 3 条，点击查看各分类摘要"
  - 用户反馈原话："希望每天某个时间，把最近收藏夹里收藏的东西总结分类分发过去"

- **场景化触发推送**
  - 基于 LBS：到达某城市时推送"你收藏了 X 篇关于这个城市的内容"
  - 基于时间：换季时推送穿搭收藏、周末推送周边游收藏
  - 基于行为：用户搜索"成都美食"时提醒"你已收藏了 8 篇相关内容"

### 4.5 完整架构关系

```
              ┌──────────────────────────────────────────┐
              │   智能触达（横向贯穿）                     │
              │   每日回顾 / 收藏周报 / 场景化推送          │
              └──────────────────────────────────────────┘
                    ↕           ↕           ↕
第一层：整理  →  让收藏有序（基础能力，覆盖沉淀/回找/清理）
    ↓
第二层：提炼  →  让收藏有用（核心价值，驱动行动转化）
    ↓
第三层：Agent →  让收藏活起来（差异化体验，深度个性化服务）
```

- 三层纵向递进：每一层以上一层为基础
- 智能触达横向贯穿：将三层能力的结果主动推送给用户，而非被动等待
- 触达本身也是各层的入口：用户从推送进入 → 看到整理结果 → 深入提炼 → 启动 Agent

## 五、产品价值

### 5.1 用户价值
- 收藏内容的复用率显著提升（从 < 15% 提升至 40%+）
- 从"收藏→遗忘"变为"收藏→整理→行动"的正向循环
- 个人知识管理零成本化——AI 代替用户完成最不愿意做的整理工作
- 决策效率提升——不再需要逐篇翻阅、手动对比

### 5.2 商业价值

**AI 服务变现：**
- 基础整理免费（降低使用门槛，扩大用户基数）
- 高级功能付费：
  - 知识提炼（Todo 生成、知识库沉淀）—— 单次付费或包月
  - Agent 交互 —— 按对话次数或订阅制
  - 高级清理（深度过期分析、智能合并）—— 增值服务
- 预估付费转化路径：免费整理体验 → 发现提炼价值 → 付费解锁

**平台价值：**
- 收藏内容二次消费 → 种草→转化链路的激活
- 用户粘性增强（收藏越多、整理越深入，越离不开平台）
- 从内容强势平台延伸出"学习助手"等工具化角色
- 差异化竞争壁垒（vs 抖音/百度/微信收藏）

### 5.3 运营与品牌价值

#### 运营活动方向

**1. 收藏健康度报告（"收藏体检"）**

- **运营价值**：年末/季度末推出，制造刷屏级传播事件
- **商业价值**：时光轴中可精准植入品牌广告（"你从去年 3 月开始关注护肤，试试这个新品"）

**3. 收藏社交（"品味匹配"）**

- **商业价值**：收藏集可嵌入商品链接，创造新的种草→转化路径；优质收藏集创作者可成为新型 KOC
- **品牌价值**：丰富平台内容生态，从"看别人的笔记"扩展到"看别人的收藏"，强化社区属性

## 九、薯管家 Agent 改版方案

### 方案命名

- **产品名：** 薯管家
- **产品定位：** 从"信息坟场"到个人知识库
- **方案全称：** 小红书主站收藏夹 Agent 改版方案

### 核心理念

将收藏夹的各项能力（整理、搜索、摘要、清理、生成）统一收束到一个 Agent 入口——「薯管家」。用户不再需要学习"哪个按钮干什么"，而是通过自然语言对话，让薯管家主动帮你管理收藏。

### 薯管家的三种工作模式

| 模式 | 触发方式 | 对应价值维度 | 示例 |
|------|----------|-------------|------|
| **被动响应** | 用户主动对话 | 好用性 | "帮我找之前收的那个上海日料" |
| **主动建议** | 薯管家气泡提醒 | 时效性 | "你有 12 条收藏可能过期了，要清理吗？" |
| **任务执行** | 对话中直接操作 | 有用性 | "已将 247 条收藏整理为 8 个分类，查看结果 →" |

### Agent 能力清单（Tools）

薯管家通过 Claude API 的 tool use 能力，可在对话中调用以下工具：

| Tool | 功能 | 用户触发示例 |
|------|------|-------------|
| organize() | 智能分类 | "帮我整理收藏夹" |
| summarize() | 知识提炼/摘要 | "总结一下我收藏的成都攻略" |
| cleanup() | 过期清理 | "清理过期内容" |
| search() | 语义搜索收藏 | "找一下之前收的那个人均80的日料" |
| generate() | 生成行程/清单/对比表 | "帮我排一个三天成都行程" |
| remind() | 定期推送/回顾 | "每周给我推送收藏摘要" |

### 交互流程

```
进入收藏页
→ 薯管家主动冒泡："好久没来了，你有 3 条收藏的店已经关了"（时效性）
→ 用户点击薯管家，进入对话
→ "帮我整理一下" → Agent 调用 organize()，结果直接渲染到页面（有用性）
→ "下周去成都，帮我从收藏里挑餐厅" → Agent 调用 search() + generate()（好用性）
```

### 技术实现

- 基于 Claude API 的 tool use（函数调用）能力
- 前端复用现有的 AgentModal 对话界面，扩展为可展示操作结果
- 后端将现有 organize、chat 等逻辑包装为 tools 传给 Claude
- 对话结果可直接驱动页面 UI 变化（如分类列表刷新、笔记高亮等）

##### Agent System Prompt

以下是薯管家 Agent 的完整系统提示词：

```
你是"薯队长"，小红书收藏夹的 AI 助手。你的角色是一个友好、专业的图书管理员，帮助用户管理和利用他们的收藏内容。

你的能力：
- 智能整理收藏夹（分类、打标签）
- 根据收藏内容生成摘要和行动建议
- 回答关于用户收藏内容的问题
- 帮用户从收藏中做决策（如：推荐餐厅、规划行程、对比产品）

你可以使用工具来执行操作。当用户要求整理收藏、搜索收藏或总结分类时，请使用对应的工具。

风格要求：
- 说话亲切自然，像朋友一样
- 回答简洁实用，不啰嗦
- 适当使用 emoji 增加亲和力
- 如果用户的问题超出收藏范围，礼貌引导回来

重要：当用户请求以下操作时，你必须调用对应的工具，而不是只用文字回复：
- 当用户说"整理"、"分类"、"帮我整理收藏"等 → 调用 organize_favorites 工具
- 当用户说"找"、"搜索"、"查找"等 → 调用 search_favorites 工具
- 当用户说"总结"、"摘要"、"概括"等 → 调用 summarize_category 工具

调用工具后，根据工具返回的结果，用友好的语言向用户说明操作结果。
```

### 与三层递进架构的关系

薯管家是三层功能架构的统一交互入口：
- 第一层（整理）→ organize() + cleanup()
- 第二层（提炼）→ summarize() + generate()
- 第三层（Agent）→ 多工具组合调用 + 多轮对话
- 横向触达 → remind() + 主动气泡

不改变功能架构本身，而是用 Agent 作为统一入口降低用户使用门槛。

## 十、设计讨论记录

### 2025-05-16 初始讨论

**方向选择：** 从搜索/推荐优化方向出发，最终聚焦到收藏夹优化。选择理由：
- 有真实用研支撑（社区求助帖 + 身边用户验证）
- 痛点普遍且共鸣度高
- Before/After 对比强烈，Demo 展示效果直观

**功能架构确认：** 三层递进设计
1. 智能整理（自动分类 + 打标签 + 过时清理）
2. 知识提炼（总结 + Todo + 知识库）
3. Agent 交互（对话式任务完成）

**展示形态确认：** Web 网页
- 电脑端：居中显示，套手机壳，模拟移动端体验
- 手机端：全屏自适应，接近原生 App 体验
- 部署到 Vercel，面试官通过链接直接体验

**商业价值讨论：**
- AI 服务可作为付费能力（总结、Agent 等）
- 平台可从内容平台延伸出"学习助手"等工具角色
- 收藏二次消费可激活种草→转化链路
- 运营活动（收藏体检/时光轴/收藏社交）兼具传播力和商业价值

**文档结构讨论：**
- 决定在方案设计前加入"数据梳理"章节
- 按用户使用收藏夹的完整旅程（收藏→沉淀→回找→使用→清理）拆解问题
- 每个阶段分析行为数据、断裂点和机会点，方案设计对应每个断裂点

**数据方案：**
- 优先使用真实收藏数据（增强 API，需公司内网）
- 备选方案：通过搜索工具抓取真实笔记 / 手写 mock 数据
- 工程策略：先定义数据接口，UI 与数据层解耦，后续灵活替换

**技术选型：** Next.js + React + Tailwind CSS + TypeScript + Framer Motion

### 2026-05-16 交互架构重设计

**问题：** 原方案的"悬浮按钮→全屏动画→结果页"流程存在以下不足：
1. 悬浮按钮的交互过于"功能化"，用户需要主动决定是否点击
2. AI 整理动画虽有仪式感，但属于一次性体验，重访价值低
3. 整理前后是完全不同的页面，用户缺乏连续的感知

**新方案：薯队长引导式交互**

核心思路：用小红书官方吉祥物"薯队长"作为 AI 助手的拟人化入口，通过对话气泡自然引导用户。

**交互流程：**
1. 用户进入收藏夹页面（收藏 tab）
2. 薯队长角色出现在页面右上区域，弹出第一个对话气泡：
   - 泛化问候："好久没来整理收藏啦～"
3. 3-5 秒后，弹出第二个气泡（基于收藏内容的个性化消息）：
   - 例："你有 23 篇美食笔记集中在成都，要不要帮你整理一下？"
   - 气泡内嵌"帮你整理一下？"按钮
4. 两条交互路径：
   - **路径 A：点击薯队长** → 进入 AI 对话界面
   - **路径 B：忽略/关闭气泡** → 页面下方自动展示已分类的收藏内容

**布局设计：**
- 薯队长对话气泡为浮动层，叠在内容上方，不占固定空间
- 内容区可以更大，信息密度更高
- "AI一键整理"按钮集成在对话气泡的第二条消息中，交互更自然

**方案优势：**
1. 降低用户决策成本——不是"要不要点按钮"的二选一，而是薯队长主动打招呼
2. 双路径设计——点薯人→对话式交互（探索型），不点→直接看分类结果（效率型）
3. 对话气泡"先泛后精"——先建立亲近感，再展示 AI 能力
4. 拟人化入口比功能按钮更有品牌温度

**入口设计决策：先进入收藏夹（而非笔记页）**

理由：
1. 场景匹配——产品解决"收藏了用不起来"的问题，收藏夹页面正是用户"想找/想用收藏"的时机
2. Before/After 对比直观——面试官先看到杂乱列表（痛点），再看到薯队长引导整理（方案）
3. 保持小红书原生页面结构——顶部 tab（笔记/评论/收藏/赞过）保留，默认停在收藏 tab
